# 👹 リアル鬼ごっこ（oni-game）

友達同士で、学校・公園・街などのリアルな空間を使って遊ぶ鬼ごっこアプリです。
地図（Google Maps）をゲームボードにして、開始地点を中心とした円形エリアで遊びます。

- 鬼には逃走者の正確な位置は見えず、「この円の中のどこかにいる」という**可能性エリア**だけが見えます
- ゲーム中に**ミッションが4回**発生し、成功すると位置がぼやけ、失敗すると絞り込まれます

## 動かし方

ビルドは不要です。ES Modules を使うため、ファイルを直接開くのではなく HTTP サーバー経由で開いてください。

```bash
# リポジトリのルートで
npm start
# または
python3 -m http.server 8000 --directory oni-game
```

ブラウザで http://localhost:8000 を開きます。
PCのブラウザの開発者ツールで「スマホ表示」にすると確認しやすいです。

### 開発モード（1台で動作確認）

http://localhost:8000/?dev を開くと開発モードになります。

- ゲーム画面の「🛠 視点」で、どのプレイヤーとして画面を見るか切り替えられます（見える情報は、そのプレイヤーの表示ルールどおりです）
- 地図をタップすると、今の視点のプレイヤーがその場所へ移動します（GPSの代わり）
- ダミーの逃走者はエリア内を歩き回り、ミッション中は7割の確率で自分の目的地へ向かいます。ダミーの鬼は可能性エリア（鬼に見える情報）を頼りに追いかけて確保を試みます

開発モードでないときは、自分の位置は端末のGPSで更新されます。

### Google Maps を使う

APIキーが無くても、方眼紙の**簡易マップ**で全機能を確認できます。Google Maps を使うときは:

1. 設定ファイルを作る
   ```bash
   cp oni-game/config/config.example.js oni-game/config/config.js
   ```
2. `oni-game/config/config.js` の `googleMapsApiKey` に自分のキーを書く

`config/config.js` は `.gitignore` 済みなので GitHub には上がりません。

#### APIキーを安全に管理するために

Google Maps JavaScript API のキーは、仕組み上ブラウザに送られるため「完全に隠す」ことはできません。
そのため、**キーが漏れても悪用されない設定**にすることが大切です。Google Cloud Console で次を設定してください。

- **アプリケーションの制限**: 「HTTPリファラー」にして、`http://localhost:8000/*` と公開先のURL（例: `https://<ユーザー名>.github.io/*`）だけを許可
- **APIの制限**: 「Maps JavaScript API」だけに限定（STEP 4 で Places API を使う場合はそれも追加）
- **割り当て（クォータ）と予算アラート**: 使いすぎたときに気付けるようにする
- キーは GitHub・スクリーンショット・チャットに貼らない。漏れたらすぐ再発行する

公開時（GitHub Pages など）は、GitHub Actions の Secrets からデプロイ時に `config.js` を生成する方式にします（公開の段階で追加予定）。

### スマホの実機で確認する

位置情報は **HTTPS**（または localhost）でしか使えません。実機で確認するときは GitHub Pages などの HTTPS で公開するか、
`npx cloudflared tunnel --url http://localhost:8000` のようなトンネルを使ってください。

## オンライン（Firebase）で動かす（STEP 7-B 時点）

STEP 7-B 時点でオンラインで動くのは、**部屋の作成・4桁コードでの参加・メンバーの同期・在席表示**だけです。
ゲームの開始以降（7-C〜）はまだ端末内モードでしか遊べません。

### ローカルのエミュレーターで試す（本番には接続しない）

必要なもの: Node.js 22、Java 11 以上（RTDB エミュレーター用）

```bash
npm install                 # Firebase CLI・テスト用ライブラリ
npm run functions:install   # Cloud Functions の依存
npm run emulators           # Auth・RTDB・Functions のエミュレーターを起動（projectId: demo-oni-game）
```

別のターミナルで `npm start` し、ブラウザで http://localhost:8000/?backend=firebase を開きます。
2つのブラウザ（片方はシークレットウィンドウ）で開くと、別々の匿名ユーザーとして部屋の作成・参加を試せます。

- `demo-` で始まるプロジェクトIDは、Firebase の仕様でエミュレーター専用です（本番のサービスには接続されません）
- `?dev` を付けると、常に端末内モード（ダミーの友達）で動きます

### テスト

```bash
npm test               # ゲームロジックのテスト（エミュレーター不要）
npm run test:emulator  # Security Rules・部屋の作成/参加・在席のテスト（エミュレーターを自動で起動・停止）
```

### 本番の Firebase を使うとき（まだ不要）

- Firebase コンソールで作ったウェブアプリの設定を `oni-game/config/config.js`（Git 管理外）の `firebase.production` に書き、`firebase.mode` を `'production'` にする
- プロジェクトIDは `firebase deploy --project <本番のID>` のように指定する（`.firebaserc` はエミュレーター用の `demo-oni-game` のまま）
- Cloud Functions を使うには Blaze（従量課金）プランが必要。予算アラートを設定すること
- ウェブの API キーは秘密鍵ではないが、アクセスの制御はすべて Authentication と Security Rules・Cloud Functions で行う（キーを隠すことを守りの前提にしない）

## 現在できること（STEP 1）

1. **ホーム**: 名前入力、ゲーム作成、ルームコード入力（参加はFirebase導入後）、遊び方と安全上の注意
2. **ゲーム作成**: ゲーム時間（5〜60分）、エリア半径（100m〜5km）、初期ぼかし（50m〜1km）、鬼の人数（1〜10人）、位置の公開間隔（30秒〜5分）、鬼の位置を逃走者に見せるか、確保距離、増え鬼
3. **開始地点**: 現在地を使う、または地図タップで選ぶ。エリアの円がその場でプレビューされる
4. **ルーム**: ルームコード表示、招待リンクの共有、参加者一覧、ダミーの友達の追加（開発用）
5. **ゲーム開始**: 鬼をランダムに決定（複数鬼対応）、地図にエリア・開始地点・プレイヤーを表示、残り時間のカウントダウン

## 現在できること（STEP 2）

- **ゲーム進行**: 開始で `playing`、開始時刻と終了時刻を記録、残り時間を表示、時間切れで `finished`
- **プレイヤー**: ID・名前・役割・状態（active / caught）・確保された時刻・確保した鬼・ミッション履歴・位置ぼかし精度
- **鬼の決定**: 設定した人数をランダムに決定（複数鬼対応）。バッジ・マーカーの色とアイコンで鬼と逃走者を区別
- **ゲームエリア**: エリアの外に出ると警告を表示（ゲーム画面はそのまま）
- **確保**: 鬼の「確保！」ボタン。確保距離（5/10/20/30m）以内の逃走者のうち**最も近い1人**を確保。
  操作のあと3秒は再操作できない（連打で近くに人がいるか探れないようにするため）
- **増え鬼**: ON なら捕まった逃走者が鬼になる、OFF なら脱落（観戦のみ）
- **勝敗**: 時間切れで逃走者が1人でも残れば逃走者の勝ち、全員確保で鬼の勝ち（同時なら鬼の勝ち）。ホストは途中終了もできる
- **終了時**: GPSの監視を止め、保持していた実位置を消去

## 位置情報のプライバシー（STEP 3）

鬼には逃走者の正確な位置を渡さず、「この円の中のどこかにいる」という**可能性エリア**だけを渡します。

### 表示ルール（ゲーム中）

| 見る人 ＼ 見られる人 | 鬼 | 参加中の逃走者 | 脱落者 |
| --- | --- | --- | --- |
| 鬼 | 位置を表示 | **可能性エリアだけ**（紫の円＋❓） | 表示しない |
| 参加中の逃走者 | 位置を表示（設定でOFFにできる） | 位置を表示（仲間） | 表示しない |
| 脱落者 | 位置を表示（設定でOFFにできる） | **表示しない**（鬼に教えられないように） | 表示しない |

- 自分の位置は常に表示。逃走者は「鬼にどう見えているか」（自分の可能性エリア・青い円）も見られます
- ロビー・ゲーム終了後は、誰の位置も表示しません

### 可能性エリアの作り方（`js/game/privacyArea.js`）

R = その逃走者の現在の `blurM`（円の半径）

1. 逃走者ごとに、ゲーム内部だけの**秘密の値**（シード・マス目の回転と原点のずれ）を暗号学的乱数で作る
2. 秘密のマス目（一辺 0.9R）で、実位置が入っているマスを選ぶ。前回のマスの中心から 0.65R 以内なら前回のマスを使い続ける（境界での行ったり来たりで円が切り替わらないように）
3. マスの中心から、「秘密のシード＋公開回数＋マス」で決まる量（最大 0.25R）だけずらした点を円の中心にする

- 可能性エリアは**最後に公開した時点の実位置を含むスナップショット**です。
  公開した時点の実位置は必ず円の中（中心から最大 0.9R）にあり、中心とは 0.1R 以上離れます。
  公開後に逃走者が移動すれば、現在位置が古い円の外に出ることは仕様上あり得ます（次の公開で新しい円になります）
- マスの中で動いても円は動かず、公開ごとのずらしは移動方向と無関係になるように作っています
- 中心はマスに結びついているため、止まっている逃走者の円を何回分平均しても、平均位置はマスの中心付近に集まり、実位置そのものには近づきにくい設計です

**検証結果（保証ではありません）**: `tests/privacy.test.js` と同じ条件（R=300m、ランダムな位置と秘密の値で200人分）で、
止まっている逃走者の円の中心を平均し、実位置との距離を測りました。

| 平均した回数 | 1回 | 10回 | 200回 |
| --- | --- | --- | --- |
| この方式 | 約122m | 約110m | 約105m |
| 毎回単純にランダムにずらす方式（比較） | 約183m | 約53m | 約12m |

今回のシミュレーション条件では、200回の公開でも、平均位置が実位置の近く（例えば数十m以内）に収束する様子は確認されませんでした。
一方、比較用の単純な方式は約12mまで近づきました。これは平均による推測に対する検証結果であり、
他の推測方法（移動の癖、地形、確保ボタンの結果、複数の情報の組み合わせなど）に対して実位置が分からないことを数学的に保証するものではありません。
また、1回の円だけでも、実位置は「中心から 0.9R 以内」にあるため、円全体よりやや狭い範囲に絞れます。

### 公開間隔（`js/game/locationPublisher.js`）

- 「位置の公開間隔」（30秒〜5分）ごとに、全逃走者の可能性エリアを作り直す
- 間隔の途中は、GPS が更新されても円は変わらない（開始後に初めて位置が届いた人だけ、その時点で1回公開）
- `blurM` はミッション結果（STEP 5）で変わる予定。次の公開から新しい大きさの円になる
- 確保された逃走者の円はすぐに取り下げる。ゲームが終わると、実位置・秘密の値・公開済みの円をすべて消す

### データの流れ

```
GPS ─▶ state.positions（実位置・内部のみ）
          │ 公開タイミングだけ
          ▼
   privacyArea.js（秘密の値を使う）─▶ state.privacy.published（可能性エリア・内部）
                                          │
                  visibility.js（見る人ごとに必要なものだけ）─▶ 各プレイヤーのビュー ─▶ 画面
```

### Firebase 導入後（STEP 7）の構成予定

- 実位置: 本人だけが書き込め、**クライアントからは誰も読めない**場所に置く
- 可能性エリアの計算（`locationPublisher.js`・`privacyArea.js`）、確保判定、ビュー作成（`visibility.js`）は Cloud Functions で実行。秘密の値もサーバーだけが持つ
- 鬼の端末が購読できるのは、公開済みの可能性エリアと鬼の位置だけ（セキュリティルールで制限）
- 「鬼の端末に実位置を送ってから画面で隠す」構成にはしない

## ミッション（STEP 4）

1ゲームにつき必ず4回。「制限時間内に指定された場所（🎯）へ到達せよ」。

### 発生時刻（`js/game/missionSchedule.js`）

- ゲーム開始時に4回分の発生時刻を決める（暗号学的乱数）。**次の発生時刻はプレイヤーに知らせない**
- 制限時間 = ゲーム時間の10%（60秒〜5分）。開始直後・終了直前（各8%）には発生させない。ミッション同士は重ならず、最低間隔（4%）をあける
- 余った時間の半分を均等、半分をランダムに配るので、ゲーム全体に散らばる
- 正式に選べるゲーム時間（5・10・20・30・60分）のすべてで4回成立することをテストしている。短いゲームでは制限時間を縮めて4回入れる
  （内部テストとして、UIにない長さ（3〜60分の各分）でも成立することを確認。4回入らない長さはエラーにして、黙って回数を減らさない）

例（乱数により毎回変わる）:

| ゲーム時間 | 制限時間 | 発生〜終了 |
| --- | --- | --- |
| 5分 | 45秒 | 0:31〜1:16 / 1:38〜2:23 / 2:42〜3:27 / 3:48〜4:33 |
| 10分 | 60秒 | 1:17〜2:17 / 3:37〜4:37 / 5:37〜6:37 / 7:44〜8:44 |
| 30分 | 3分 | 5:16〜8:16 / 12:25〜15:25 / 18:07〜21:07 / 23:28〜26:28 |

### 目的地（`js/game/destinations.js`）

- 逃走者ごとに、本人の現在地から**直線距離で**一定の範囲（最短35m〜制限時間に応じた上限）に作る。
  道のりの長さは考慮していないため、「歩いて届くこと」は保証しない
- ゲームエリアの内側で、境界から30m以上離す
- ホストが作成画面で置いた**除外エリア**（灰色の円）の近くには作らない
- APIキー不要の**仮想目的地**で動く。大きなエリア向けに、Places などの施設候補を種類で絞り込む処理も用意済み（APIの呼び出しは未実装）

**安全性について（重要）**: 仮想目的地は地図データ（道路・建物・水辺など）を使っていません。

| 目的地にしない場所 | 今の仕組みでの扱い |
| --- | --- |
| ゲームエリアの外・境界ぎりぎり | 自動で除外 |
| 直線距離で遠すぎる場所 | 自動で除外 |
| 車道 / 川・池・海などの水域 / 私有地 / 立入禁止区域 / 危険な場所 / 建物の中 | **自動判定できない**。ホストの除外エリアで除外する |
| 塀や線路の向こうなど、実際には行けない場所 | **自動判定できない**。除外エリア、または逃走者の目的地変更で対応 |

つまり、アプリが保証するのは「エリア内」「除外エリアから離れている」「直線距離で範囲内」の3点だけで、
目的地の安全性は**ホストが安全な場所をゲームエリアに選ぶことと、除外エリアの設定に依存**します。

### 目的地の変更

- 逃走者は**1ゲームにつき1回だけ**、目的地を変更できる（行けない・危ない場所だったとき用。失敗扱いにしない）
- 変更後の目的地も同じルール（エリア内・除外エリア・直線距離）を通す
- 変更したこと・変更した時刻は鬼にも他の逃走者にも知らせない（ログにも残さない）

### 到達判定・結果（`js/game/mission.js`）

- 実位置が目的地から **20m以内**に入ったら成功（位置の更新時とタイマーで判定）
- 制限時間までに到達しなければ失敗。ミッション中に確保された人は無効
- ゲームが終わると、進行中のミッションは無効で終了し、以降は発生しない
- 結果は各プレイヤーの `missionHistory` に記録（STEP 5 で blurM の変更に使う）

### ミッションとプライバシー

- 発生前: 発生時刻・目的地は誰のビューにも入らない
- 発生中: 目的地は**本人のビューだけ**。鬼には「発生中・何回目・残り時間」だけ
- 結果: 本人にはすぐ。ほかの人（鬼を含む）には、ミッション終了後に**成功・失敗の人数だけ**
  （到達した瞬間を知らせると、その時刻から位置を推測される手がかりになるため）
- ミッション中も可能性エリアの仕組みはそのまま（実位置は公開しない）
- 到達判定は実位置を持つ側（今は端末内、Firebase 導入後はサーバー側）で行う

## ミッション結果による位置ぼかしの変化（STEP 5）

`js/game/blurPolicy.js` に段階と変更ルールをまとめています（値の調整はこのファイルだけ）。

- 段階: **50 / 100 / 150 / 200 / 300 / 400 / 500 / 750 / 1000 m**（下限 50m・上限 1000m）
- 成功 → **1段階大きく**（鬼に分かりにくくなる）/ 失敗 → **1段階小さく** / 無効 → 変えない
- 例: 初期 300m（9段階の真ん中）から、4回全部成功で 1000m、全部失敗で 50m
- 変わるのはミッション終了時。確保されて脱落した人・鬼になった人（増え鬼）は変わらない。ゲーム終了後も変わらない

### 鬼に見える円への反映

- ミッション終了時に変わるのは内部の `blurM` だけで、**今見えている円はそのまま**
- **次の位置公開から**新しい大きさの円になる（STEP 3 の公開間隔の仕組みをそのまま使う）
- 逃走者本人には「ミッション成功！ 位置情報のぼかしが強くなりました（300m → 400m・次の位置公開から反映）」のように表示。
  画面上部にも「今は半径300m（次の位置公開から半径400m）」と表示
- 鬼には、ぼかしが変わったという通知も `blurM` の値も渡さない。鬼に分かるのは、次の公開で円の大きさが変わることだけ
  （ミッション終了時の「成功○人・失敗○人」の集計は STEP 4 どおり全員に表示）

## ゲーム終了と結果画面（STEP 6）

### 終了処理（`gameState.js` の `finish()`）

1. 勝敗を決める（時間切れで逃走者が残っていれば逃走者の勝利 / 全員確保で鬼の勝利 / 同時なら鬼 / ホストの途中終了は勝敗なし）
2. 実位置・秘密値・公開済みの可能性エリアを破棄し、進行中のミッションを無効で終える（以降は発生しない・blurM も変わらない）
3. **破棄した後の状態から** `buildResultSummary()` で結果データを作る
4. ゲーム画面は GPS の監視を止めて結果画面へ移る

### 結果データ（`js/game/resultSummary.js`）

画面にも Firebase にも依存しない純粋な関数。位置情報（`positions`・`privacy`・目的地）を読まない。

| 含めるもの | 含めないもの |
| --- | --- |
| 勝者・決着理由・見出し・ゲーム時間・プレイ時間・増え鬼の有無 | GPS座標・移動履歴・GPS更新履歴 |
| 名前・開始時の役割・最終的な役割・役割の変化・確保された「開始◯分台」・確保した人数・逃げ切り | 可能性エリアの中心と半径（blurM）・秘密値 |
| ミッション4回分の成功・失敗・無効の**人数** | 目的地・ミッション達成時刻・誰が誰を確保したか・正確な確保時刻 |
| 自分のミッション結果（本人にだけ） | 他人の個人ミッション結果 |

結果画面（`js/screens/result.js`）は `resultViewFor()` で本人向けに絞った結果データだけを表示します。

### もう一度遊ぶ

- 引き継ぐのは **ルーム・メンバー・ゲーム設定** だけ
- 開始地点と除外エリア（場所の情報）は作成画面で設定し直す
- 次のゲーム開始時に、ゲームID・秘密値・可能性エリア・ミッションのスケジュールと目的地をすべて新しく作る
  （前のゲームの実位置・可能性エリア・秘密値は残っていない）

## 設計のポイント

- **ルールと画面の分離**: `game/` はDOMや地図を知らない純粋なロジックなので、Node.js でテストできます（リポジトリ直下の `tests/`）
- **地図の差し替え**: 画面は `map/map.js` の「ボード」だけを使うので、Google Maps と簡易マップを同じコードで扱えます
- **Firebase を後から足しやすく**: 画面は `services/roomService.js` のメソッドだけを呼びます。STEP 7 では同じメソッドを持つ Firebase 版に差し替え、受け取ったデータを `gameState` に入れるだけで画面が更新されます
- **実位置と表示の分離**: 実際のGPS座標は `gameState` の `positions` にだけ持ち、Player オブジェクトには入れません。
  画面は `game/visibility.js` の `buildPlayerView()`（見る人ごとに「見せてよい情報」だけを入れたもの）しか使いません。
  鬼のビューに逃走者の座標が入らないことはテストで確認しています
- **位置情報のプライバシー**: 上の「位置情報のプライバシー（STEP 3）」を参照

- 道路への飛び出し・歩きスマホはしない
- 私有地・立入禁止区域・水辺など危険な場所には入らない
- 公園や学校など、許可のある安全な場所で遊ぶ
